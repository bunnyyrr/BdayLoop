# BdayLoop

Бэкенд для «BdayHub» - сервиса, который помогает не забывать про дни рождения друзей, дарить подарки вскладчину и обсуждать их в закрытом чате.

Проект идёт поэтапно. Цель - руками почувствовать, что именно каждый фреймворк берёт на себя, поэтому на каждом этапе сначала всё пишется вручную, а потом заменяется инструментом.

| Этап | Что | Состояние | Где смотреть |
|---|---|---|---|
| 1. Чистая Java | Jetty + сервлеты + JDBC | готов | тег и ветка `phase-1-pure-java` |
| 2. Spring + Hibernate без Boot | Spring Framework, Hibernate, Flyway, HikariCP, Spring MVC | готов, описан ниже | тег и ветка `phase-2-spring-hibernate` |
| 3. Spring Boot | Spring Data JPA, Spring Security + JWT, Actuator, Docker, напоминания | впереди | |

## Этап 2 — Spring + Hibernate без Spring Boot

### Стек

- **Java 26**, Maven
- **Spring Framework 7** (контейнер, `@Transactional`, Spring MVC) - без Boot, всё настраивается вручную
- **Hibernate ORM 7 (JPA)** - сущности, JPQL, dirty checking, `join fetch`
- **Flyway** - миграции схемы (`src/main/resources/db/migration`)
- **HikariCP** - пул соединений
- **Embedded Jetty 12** (Servlet 6.1) с одним `DispatcherServlet`
- **Jackson 3** - JSON
- **spring-security-crypto** - только `BCryptPasswordEncoder`, без Spring Security
- **PostgreSQL 16** - в Docker
- **HttpSession** - аутентификация по cookie-сессии
- **JUnit + Testcontainers** - тесты на настоящем Postgres в контейнере
- **Postman** - коллекция из 47 запросов как контракт API (`postman/`)
- **GitHub Actions** - CI на каждый push и pull request
- Фронтенд - vanilla HTML/JS/fetch, без сборки, только для ручной проверки API

### Архитектура

```
Браузер → Jetty → DispatcherServlet → Controller → Service → Repository → PostgreSQL
```

- **Controller** (`web/controller`) - только HTTP: адреса, параметры, коды ответов
- **Service** - вся бизнес-логика, проверки прав («можно ли этому пользователю это делать»), границы транзакций
- **Repository** (`repository/i` + `repository/jpa`) - доступ к данным через `EntityManager`
- Два контекста Spring: корневой (сервисы, репозитории, база, Hibernate, транзакции) и веб (контроллеры, обработчик ошибок). Веб-контекст видит бины корневого, наоборот нет
- `AuthUser` - параметр метода контроллера: Spring сам достаёт текущего пользователя и роль из сессии, без входа отвечает 401
- Все ошибки превращает в HTTP-ответы один `@RestControllerAdvice`

### Что изменилось по сравнению с этапом 1

| Задача | Этап 1 (вручную) | Этап 2 |
|---|---|---|
| Маршрутизация HTTP | 4 сервлета, разбор пути, цепочки `if` | Spring MVC: `@RestController`, `@GetMapping` и т.д. |
| JSON | свой `JsonUtil` | конвертер Spring + Jackson 3 |
| Кто делает запрос | `requireUserId(req)` в каждом методе | параметр `AuthUser` + argument resolver |
| Ошибки | `try/catch` и `ExceptionHandler.handle` в каждом методе | один `@RestControllerAdvice` |
| Доступ к БД | JDBC, SQL руками, маппинг строк | Hibernate: сущности, JPQL, связи |
| Соединения | свой `ConnectionManager` | HikariCP, `DataSource` как бин |
| Схема БД | `schema.sql` при первом запуске контейнера | миграции Flyway |
| Транзакции | нет, импорт не атомарный | `@Transactional` в сервисах |
| Каскадные удаления | в SQL | `ON DELETE` в миграциях, проверены тестами |
| Пароли | jBCrypt напрямую | `PasswordEncoder` |
| CORS | свой `Filter` | `addCorsMappings` |
| Зависимости | создавались вручную | внедряются через конструктор |

### Объём кода

Непустые строки Java в `src/main`:

| Слой | Этап 1 | Этап 2 |
|---|---|---|
| web (сервлеты → контроллеры) | 573 | 434 |
| dao → repository | 488 | 330 |
| service | 328 | 435 |
| остальное (модель, конфиги, исключения, `Application`) | 200 | 416 |
| **всего** | **1589** | **1615** |

Общий объём почти не изменился, но поменялось, где он лежит. Веб-слой и доступ к данным стали короче, потому что маршрутизацию, разбор JSON, SQL и маппинг строк теперь делают Spring и Hibernate. Сервисов стало больше: в них переехали проверки прав, смена пароля и атомарный импорт. В «остальном» выросли сущности Hibernate с аннотациями и конфигурация.

### Доменная модель

`users`, `groups`, `group_members`, `group_subscriptions`, `subscriptions`, `gifts`, `messages`. Схема собирается миграциями:

- `V1__init.sql` - таблицы
- `V2__fk_indexes.sql` - индексы по внешним ключам
- `V3__messages_sender_set_null.sql` - автор сообщения может быть пустым (`ON DELETE SET NULL`)

Участие в группе (`group_members`) и подписка на группу (`group_subscriptions`) - это разные вещи. Получатели уведомлений = прямые подписчики плюс участники групп, на которые подписан получатель.

При удалении аккаунта удаляются его подарки, подписки, участие в группах и сообщения в его собственном чате. Сообщения, которые он писал в чужих чатах, остаются с подписью «аккаунт удален». Группа без создателя остаётся, управлять ею может только администратор.

### Функциональность

- Регистрация, вход/выход, роль `USER`/`ADMIN`
- Поиск пользователей по имени и username
- Профиль: редактирование, смена пароля (с проверкой старого, после смены сессия обновляется)
- Группы: создание, поиск, вступление/выход, подписка/отписка, переименование, удаление, список участников с именами
- Подарки: добавление, удаление, список по пользователю
- Чат про подарок: доступ только по подписке (личной или через группу), у сообщений видно имя автора
- Массовый импорт пользователей администратором: всё или ничего, в ошибке указан номер строки («Строка 3: Логин «petya» уже занят»)

### Запуск

**0. Java**

Нужна Java 26. Maven берёт её из `JAVA_HOME`, поэтому, если `mvn -v` показывает другую версию (на macOS):

```bash
export JAVA_HOME=$(/usr/libexec/java_home -v 26)
```

**1. База данных**

```bash
cp .env.example .env   # заполнить POSTGRES_DB / POSTGRES_USER / POSTGRES_PASSWORD
docker compose up -d
```

**2. Бэкенд**

Запустить `Application.main()`. Те же три переменные можно задать в Run Configuration или оставить в `.env` в корне проекта, приложение читает его само. Миграции Flyway применяются при старте. Сервер поднимается на `http://localhost:8080`.

**3. Фронтенд**

```bash
cd frontend
python3 -m http.server 8123
```

Открыть `http://localhost:8123/html/login.html`.

### Проверка API

Коллекция `postman/bdayloop.postman_collection.json` описывает контракт API (47 запросов с проверками). Импортировать в Postman и запустить через Runner, либо из терминала при запущенном приложении:

```bash
npx newman run postman/bdayloop.postman_collection.json
```

### Тесты и CI

```bash
mvn test
```

85 тестов: репозитории и сервисы работают на настоящем Postgres, который Testcontainers поднимает в Docker на время прогона (нужен запущенный Docker), плюс тесты DTO. GitHub Actions гоняет тот же `mvn test` на каждый push и pull request.

### Осознанно отложено на этап 3 (Spring Boot)

- Напоминания о днях рождения
- Unit-тесты сервисов с Mockito и тесты веб-слоя
- Вход через JWT вместо серверной сессии (сейчас после смены пароля живыми остаются сессии на других устройствах)
- Проверка длины и сложности пароля, ограничение числа попыток входа
- Docker-образ приложения и запуск одной командой
